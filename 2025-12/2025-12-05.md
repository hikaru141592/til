

# Rubyの特徴

- 1995年リリース
  - Perlのテキスト処理能力やPythonのオブジェクト指向、Lispの柔軟性などを取り入れながら、日本文化的な感性も融合させた。
  - プログラマの幸せを第一に考え、人間が自然に読み書きできる文法を追求した。
  - Windows95が発表された年でインターネットが普及
  - インターネットの世界はPC1台で完結するものではなく、複数のPCが繋がり合うことで成り立っている。そのため、より複雑な処理が求められるようになった。
- Railsが2004年にリリース

## オブジェクト指向（OOP）
| 観点             | オブジェクト指向言語（例：Ruby / Java / Python） | 非オブジェクト指向言語（例：C / COBOL / Fortran） |
| -------------- | ---------------------------------- | ---------------------------------- |
| **基本概念**       | オブジェクトを中心として設計           | 手続きを中心として設計                 |
| **コードの再利用性**   | 高い  | 低め          |
| **拡張性・保守性**    | 高い、変更に強く、大規模開発向き                   | 規模が大きいと複雑になり保守が難しくなりがち             |
| **学習コスト**      | 比較的高い（概念が多い）                      | 比較的低い                |
| **処理速度**       | オブジェクトの仕組みがある分遅い           | 速い                  |
| **メモリ効率**      | 抽象化の分、比較的良くない              | 良い             |
| **大規模開発**      | 高い適性（役割分担・再利用・テストがしやすい）            | 適性は低め（複雑化しやすい）                     |
| **小規模スクリプト**   | やや重くなることも                          | 適性が高い（シンプルでスピーディ）                  |
| **用途**         | Webアプリ、ゲーム、業務システムなど              | 組み込み、システム開発、高速処理分野など               |

## OOP言語同士の比較
| 観点              | **Ruby**                  | **Java**                      | **比較**                                   |
| --------------- | ------------------------- | ----------------------------- | -------------------------------------------------- |
| **コンパイル** | インタプリタ言語         | コンパイル言語               | Rubyはコンパイル不要だが遅い |
| **オブジェクト指向の性格** | 純粋（ほぼ全部がオブジェクト）         | 厳密（OOPルールが強制）               | Rubyは直感的で美しいコードになりやすい。Javaはルールが揃った堅牢な設計になりやすい。 |
| **値の扱い**        | 数値・nil・true/false もオブジェクト | プリミティブ型とオブジェクトが分かれている         | プリミティブ型はメソッドを持てない分軽くて高速                 |
| **型システム**       | 動的型付け                | 静的型付け                   | Rubyは試し書き・素早い開発が得意。Javaはコンパイル段階で多くのエラーを防げる。        |
| **クラス構造**       | クラス無しでも動く     | 全てクラスの中に書く必要がある               | Javaは規律のある構造で大規模管理がしやすい。         |
| **クラスの再定義**       | 可能     | 不可               | Rubyは柔軟な開発に強い。         |
| **継承・拡張**       | 単一継承＋moduleで自由度高い         | 単一継承＋interfaceで明確に分離          | Rubyは実装がラク。Javaは大規模でも衝突しにくい構造になる。                  |
| **メソッドの扱い**     | なんでもメソッド呼び出し              | プリミティブはメソッド不可                 | Rubyは統一感が高く理解しやすい。Javaは軽量なプリミティブで高速処理が可能。          |
| **設計ルール（厳しさ）**  | ルールがゆるく柔軟                 | アクセス修飾子・抽象クラス・インターフェースのルールが厳密 | Rubyは“簡単に動く”が、Javaは“設計を破綻させにくい”。                   |
| **柔軟性**         | とても高い                     | 比較的低い（設計ありき）                  | Rubyは素早く変更可能。Javaは安定重視。                            |
| **学習コスト**       | 低め／直感的                    | 型・構造の理解が必要でやや高い               | Rubyは初心者向き。Javaは基礎力をしっかり育てられる。                     |
| **大規模開発適性**     | 小〜中規模向き                   | 大規模向き                         | Rubyはスピード重視の開発に最適。Javaは企業システムなど長期間運用に強い。           |

- 大規模なソフトや複雑なシステムを作るならオブジェクト指向言語が有利
- 高速処理や小規模なプログラムなら非オブジェクト指向言語も魅力的
