# スクリプト言語

## 1. 代表的なスクリプト言語

- JavaScript
- Ruby
- Python
- PHP
- Perl

## 2. 意味

- 以下のような軽量な処理をする言語を指していた。
  - 既存ソフトを操作する
  - 自動化する
  - 補助的に機能を拡張する
- 例
  - シェルスクリプト
  - Webページを動かす JavaScript
  - マクロ言語

## 3. スクリプト言語の定義

- スクリプト言語 = インタプリタ型 ？
  - 元々は概ねそうと言えたが、これは正しくない。
  - 現代はスクリプト言語もコンパイルを行うことが多い
- スクリプト言語に厳密な定義はない。
  - スクリプト言語は技術的な実行方式の分類ではなく、歴史的・文化的に使われてきた呼び方に近い。

## 4. クライアントサイドスクリプトとサーバーサイドスクリプト

- Webアプリケーションでは処理が行われる場所によってスクリプトを分類できる。
  - クライアントサイドスクリプト
    - ユーザーのブラウザ上で実行
      - 画面の動的変更
      - 入力チェック（バリデーション）
      - アニメーション
      - 非同期通信（API呼び出し）
    - 代表的な言語
      - JavaScript
  - サーバーサイドスクリプト
    - Webサーバー上で実行
      - データベース操作
      - 認証・認可
      - ビジネスロジック処理
      - HTML生成
    - 代表的な言語
      - Ruby
      - Python
      - PHP
      - JavaScript（Node.js）
- <details>
    <summary>なぜJSだけがクライアントサイドスクリプト？</summary>

    - JavaScriptはブラウザ上で動く言語として開発されたもので、それが標準化されたため
    - ブラウザはJavaScriptのみを標準搭載している
      - Webの標準仕様で、HTML、CSS、JavaScriptが「ブラウザの基本構成」として定義された
        - 1995年NetscapeがブラウザにJavaScriptを搭載
        - その後標準化されブラウザで動く唯一の言語となる（例外あり）
  </details>

- Node.js
  - JavaScriptをサーバーサイドスクリプトとして使えるようにするための実行環境
  - <details>
    <summary>なぜそのような実行環境が必要？</summary>

    - JavaScriptはブラウザ内で動かすために作られた言語
      - ファイル操作、ファイル操作、ソケット通信、プロセス実行等ができない
      - OS上で動くような汎用スクリプトではない
    - Node.jsはJavaScriptをサーバーでも動かせるようにした環境
      - JavaScriptに、ファイル操作、ネットワーク待ち受け、OSアクセスを追加
      - JavaScriptを「普通の言語」に拡張したものと言える
    </details>

## ECMAScript

- Firefoxの開発で有名なMozilla Foundationとマイクロソフトそれぞれで開発された JavaScriptをECMAインターナショナルが標準化しECMAScriptが定められた。
- マイクロソフト製の JavaScriptは JScriptと呼ばれていた。
- ECMAScriptの使用に沿ってChromeやFirefoxやEdgeといったブラウザが実装された。
