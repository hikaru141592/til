## 学習内容1
- **タグ**: Docker
- **タイトル**: docker compose downでDBが消える現象について。
- **内容**:
  - `docker compose down`ではDBが永続化されるケースと永続されないケースがある。
    - `docker-compose.yml`で名前付きボリュームを明示的に定義しておくと永続化可能。
      ```
      # db-dataという名前のボリュームとする
      services:
        db:
          image: postgres:15
          volumes:
            - db-data:/var/lib/postgresql/data
      volumes:
        db-data:
      ```
    - `volumes:`があるが名前がない場合、Dockerが一時的にマウントされただけの匿名ボリュームを自動的に作るが、コンテナが削除されるとデータも一緒に消える。
      ```
      services:
        db:
          image: postgres:15
          volumes:
            - /var/lib/postgresql/data
      ```
    - `volumes:`がない場合、var/lib/postgresqlはコンテナ内の書き込み領域にしか存在せず、Dockerはホストにボリュームを割り当てていないためコンテナが削除されるとデータも一緒に消える（つまり匿名ボリュームですらないコンテナ内ローカルデータ）。
      ```
      services:
        db:
          image: postgres:15
      ```
  - 名前付きボリュームではDBはコンテナの外部にDBデータが保持される。
