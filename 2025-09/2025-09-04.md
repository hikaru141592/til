## 学習内容1
- **タグ**: ルーティング, RESTful
- **タイトル**: RESTfulルーティングとは
- **内容**:
1. RESTfulルーティングとは
- REST(Representational State Transfer)に基づいたURL設計の考え方。
- 「リソース（資源）」を中心に、HTTPメソッドと組み合わせて、意味のあるURLと処理の対応付けを行う。
- Railsは`resources`もしくは`resource`ヘルパーで自動的にRESTfulなルートを生成できる。

2. 基本の7アクションとHTTPメソッド対応

| アクション | HTTPメソッド | URL例            | 用途       |
|------------|-------------|------------------|------------|
| index      | GET         | /users           | 一覧表示   |
| show       | GET         | /users/:id       | 個別表示   |
| new        | GET         | /users/new       | 新規作成フォーム |
| create     | POST        | /users           | 新規作成処理 |
| edit       | GET         | /users/:id/edit  | 編集フォーム |
| update     | PATCH/PUT   | /users/:id       | 更新処理   |
| destroy    | DELETE      | /users/:id       | 削除処理   |

3. `resources`と`resource`の違い
- `resources`
  - ID付きのルートを生成（例: `/users/:id`）
  - 複数ユーザーや複数投稿などの管理に使う
- `resource`
  - IDなしのルートを生成（例: `/session`）
  - 1ユーザーにつき1つしか持たないリソースに使う（例: セッション、プロフィール、設定など）

## 4. ネストされたルート
- 親子関係を表現するルーティング。
  ```
  resources :users do
    resources :posts
  end
  # → /users/:user_id/posts/:id
  ```

## 5. コレクションとメンバー
- RESTfulで表現しにくい処理を追加する方法。
```
resources :articles do
  collection do
    get :search   # /articles/search
  end
  member do
    post :publish # /articles/:id/publish
  end
end
```
- collection: 複数全体に対する操作（検索など）
- member:     個別リソースに対する操作（公開、承認など）

## 6. RESTfulルーティングのメリット
- URLを見ただけで処理の意味がわかる
- Railsの規約に沿うのでチーム開発でも迷いにくい
- 自動生成される パスヘルパーが直感的
- API設計にも転用できる

## 7. パスヘルパー名の規則
- 基本形は以下の通り。
  - `[new|edit]_リソース名[_親リソース名]_path`
