## 学習内容1  
- **タグ**: ActionMailer, SMTP  
- **タイトル**: production.rbでのSMTP設定とエラー制御  
- **内容**:  
  - `config.action_mailer.delivery_method = :smtp`  
  - `config.action_mailer.smtp_settings` に環境変数を渡してMailgunサーバー（EUリージョンの場合は `smtp.eu.mailgun.org:587`）を指定  
  - `config.action_mailer.raise_delivery_errors = true` で配信失敗時に例外を投げ、ログに原因を残す  
  - `config.action_mailer.perform_deliveries = true` を必ず設定し、SMTP接続を実行  
  - `config.action_mailer.default_url_options = { host: "www.tamago-wakuwaku.com", protocol: "https" }`

## 学習内容2  
- **タグ**: ActiveJob, deliver_now, deliver_later, Heroku  
- **タイトル**: deliver_nowとdeliver_laterの違いとHerokuでの非同期ジョブ問題  
- **内容**:  
  - `.deliver_later`：ActiveJobにジョブ登録、デフォルトの`:async`アダプターはWeb dynoではすぐ切断されて実行されない可能性あり  
  - `.deliver_now`：即時同期送信。テストデバッグ時や本番リクエスト内で確実にSMTP接続したい場合に利用  
  - 本番環境で即時処理させるには、`config.active_job.queue_adapter = :inline` を `production.rb` に追加  

## 学習内容3  
- **タグ**: ApplicationMailer  
- **タイトル**: 送信元メールアドレスと環境変数のフォールバック設定  
- **内容**:  
  - `ApplicationMailer` の `default from:` は認証済みドメインにする必要がある、一致していない場合適切にメールが送れない。  
  - 環境変数 `MAILGUN_SMTP_LOGIN` が unset の場合に備えて、  
    ```ruby
    default from: ENV.fetch("MAILGUN_SMTP_LOGIN", "from@example.com")
    ```  
    のようにフォールバックを設定し、開発環境への影響を回避する。

## 学習内容4  
- **タグ**: Custom Domain, SSL  
- **タイトル**: Herokuカスタムドメインの設定と自動SSL管理  
- **内容**:  
  1. Heroku Dashboard → Settings → Domains で `www.tamago-wakuwaku.com` を追加  
  2. DNSプロバイダで CNAME レコードを `sinuous-...herokudns.com` に指定  
  3. `heroku certs:auto:enable --app アプリ名` で Let’s Encrypt 自動証明書を生成  
  4. `heroku certs:auto` で証明書ステータス確認、数時間で`Cert issued`→独自ドメインHTTPSアクセスが可能に

## 学習内容5  
- **タグ**: ドメイン, WHOIS, お名前.com  
- **タイトル**: お名前.comでのWHOIS情報公開とオプションの扱い  
- **内容**:  
  - ドメイン取得時に必須のWHOIS情報は必ず入力・レジストリに提出される。  
  - WHOIS情報公開代行（代理公開）は「公開される情報を隠す」有料オプションであり、未申込でもドメイン停止にはならない。  
  - ドメインプロテクションなど他のオプションも同様に任意。契約が別途発生しない限り、ドメイン本体の有効性には影響なし。

## 学習内容7  
- **タグ**: 環境変数, Heroku  
- **タイトル**: Heroku Config Varsの運用  
- **内容**:  
  - `heroku config`で現在値を一覧し、空欄や誤設定がないか随時確認  
  - `heroku config:set KEY=VALUE --アプリ名` で上書き  
  - 環境変数変更後は dyno の再起動（`heroku restart`）を忘れないこと
