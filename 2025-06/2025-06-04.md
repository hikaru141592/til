## 学習内容1  
- **タグ**: セキュリティ  
- **タイトル**: .find(params[:id])によるリスク
- **内容**:  
```
def update
  @profile = Profile.find(params[:id])
  if @profile.update(profile_params)
    redirect_to xxx_path
  else
    render :edit
  end
end
```
以上のコードのようにすると、ブラウザのアドレスバーでidを書き直すだけで簡単に他ユーザーのプロフィールを更新できてしまう可能性がある。  
`@profile = current_user.profile`のようにすることで対策が可能。

## 学習内容2  
- **タグ**: 例外  
- **タイトル**: saveとsave!
- **内容**: 
```
def create
  @article = Article.new(article_params)
  if @article.save!
    redirect_to @article
  else
    render :new
  end
end
```
以上のコードのようにすると、save!に成功した場合はIF分岐に入りリダイレクトがされるが、失敗した場合はelseの処理は行われずエラー画面が表示される。  
これはsave!が失敗時にfalseを返すのではなく例外を発生させるためで、elseの処理に移らせたい場合はsave!ではなくsaveを使う。

## 学習内容3  
- **タグ**: enum
- **タイトル**: 自動生成メソッドの上書き
- **内容**: 
```
class Withdrawal < ApplicationRecord
(〜中略〜)
  enum status: { apply: 10, accept: 20, complete: 30, cancel: 40 }
(〜中略〜)
  def self.apply(user, amount)
(〜以下略〜)
```
enum status: { apply: 10, … } を定義すると、Railsは自動的にWithdrawal.apply（状態がapplyのレコードを返すスコープ）やWithdrawal.acceptのようなクラスメソッド・スコープを生成する。  
さらに出来上がったインスタンスに対してもwithdrawal.apply!やwithdrawal.apply?などのメソッドも生成。
一方で同じクラス内に`self.apply(user, amount)`を定義するとと、Withdrawal.apply はスコープではなくクラスメソッドself.applyとして上書きされてしまう。  
そのため`self.apply(user, amount)`のメソッド名を他のものに変えることが望ましい。

## 学習内容4  
- **タグ**: セキュリティ  
- **タイトル**: .find(params[:id])によるリスク
- **内容**: 
```
class Post < ApplicationRecord
  enum status: { draft: 1, published: 2 }
end

class PostsController < ApplicationController
  def index
    @posts = Post.where("status = '#{params[:status]}'")
  end
end
```
以上のように文字列連結で直接SQL条件を組み立ててしまうと、外部から渡されるparams[:status]の値を任意の文字列に書き換えられ不正なSQLが実行される恐れがある。  
（例：params[:status] = "draft' OR 1=1; --"）  
SQLを直接文字列として書かずプレースホルダー（バインドパラメータ）を使うことで対応可能。
たとえば、以下のようにすれば、Rails（ActiveRecord）が自動的にパラメータをエスケープしてくれるため、安全。
  - 例1：バインドパラメータを使う
    @posts = Post.where("status = ?", params[:status])
  - 例2：enumの仕組みを活かす
    # statusは enum なので、シンボルや文字列で渡せば ActiveRecord が内部で値を整数に変換してくれます。
    @posts = Post.where(status: params[:status])
いずれの場合も、params[:status] の内容がそのままSQL文字列に埋め込まれず、プレースホルダー経由で安全にバインドされる。
