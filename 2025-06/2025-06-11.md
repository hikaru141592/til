## 学習内容4  
- **タグ**: Rspec, 外部認証  
- **タイトル**: RspecテストにおけるLINE認証
- **内容**:
spec/rails_helper.rbまたはspec/support/omniauth.rb等で、
```
# spec/support/omniauth.rb
RSpec.configure do |config|
  config.before(:each, type: :system) do
    # テストモード有効化
    OmniAuth.config.test_mode = true

    # モック認証情報の設定（provider:keyに合わせて）
    OmniAuth.config.mock_auth[:line] = OmniAuth::AuthHash.new(
      provider: 'line',
      uid:      '1234567890',
      info: {
        name:  'テストユーザー',
        email: 'test@example.com'
      }
    )
  end

  config.after(:each, type: :system) do
    # テストモード解除＆モック情報クリア
    OmniAuth.config.test_mode = false
    OmniAuth.config.mock_auth[:line] = nil
  end
end

```
のようにする。  
`OmniAuth.config.test_mode = true`とはテストモードを有効化するフラグで、本来はLINEなどの外部プロバイダにリダイレクトして認証を行うところをテストモードでは外部通信を一切せず、あらかじめ用意したモック認証情報（OmniAuth.config.mock_auth）を返すようにする。
これによりシステムテストやRSpecで実際のLINEアカウントを使わず安定して高速にログインフローを検証可能。

## 学習内容5  
- **タグ**: dotenv, RailsCredentials, 環境変数, 暗号化  
- **タイトル**: .envファイルとcredentials.yml.enc
- **内容**:  
  - `dotenv-rails`
    - development/test 環境で自動的に読み込まれる。  
    - production 環境では通常読み込まれず、Heroku の Config Vars や Docker の `env_file`／`environment` を使用する。  
    - 開発マシンごとにローカルで管理し、`.gitignore` で Git にはコミットしないのが一般的。  
    - `.env.example` をチーム間で共有し、本番には反映しない運用が多い。  
    - メリット：導入が簡単でファイル形式がシンプル。  
    - デメリット：暗号化がないため、誤ってコミットすると漏洩リスクがある。  
  - `credentials.yml.enc`   
    - Rails 起動時（development/test/production すべて）で暗号化されたまま読み込まれる。  
    - `config/credentials.yml.enc` と `config/master.key`（または環境変数 `RAILS_MASTER_KEY`）で管理する。  
    - マスタキーを安全に管理すれば、Git にコミットしても中身は暗号化されたままで安全。  
    - メリット：標準機能で暗号化管理が可能、環境ごとに `credentials/development.yml.enc` などを使い分けられる。  
    - デメリット：編集に `rails credentials:edit` コマンドが必要で、少し手間がかかる。  
  - 使い分け
    - 開発中の簡易管理には `.env`（dotenv）が適している。  
    - 本番環境も含めて一元的かつ安全に管理するには `credentials.yml.enc` が適している。
