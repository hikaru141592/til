- **タグ**: RSpec, Sorcery  
- **タイトル**: パスワードリセット機能のRequest Spec  
- **内容**:  
  1. ルーティングに合わせて正しい HTTP メソッド・パスを使用する  
     - `POST /password_resets` → `password_resets_path`  
     - `GET  /password_resets/create` → `password_resets_create_path`  
     - `GET  /password_resets/edit?token=...` → `edit_password_reset_path`  
     - `PATCH /password_resets/update` → `update_password_reset_path`  
  2. `edit`と`update`アクションではSorcery が発行するトークンを`params[:token]`として渡す  
     ```
     user.deliver_reset_password_instructions!
     get edit_password_reset_path, params: { token: user.reset_password_token }
     ```  

## 学習内容2  
- **タグ**: RSpec, ActiveRecord, PendingMigration, maintain_test_schema  
- **タイトル**: テスト実行時に未適用マイグレーションを自動適用するカスタマイズ  
- **内容**:  
  1. `spec/rails_helper.rb` の `maintain_test_schema!` を拡張  
     ```ruby
     begin
       ActiveRecord::Migration.maintain_test_schema!
     rescue ActiveRecord::PendingMigrationError
       puts '⚙️ Pending migrations detected. Running db:migrate for test environment...'
       system('RAILS_ENV=test bin/rails db:migrate')
       ActiveRecord::Migration.maintain_test_schema!
     end
     ```  
  2. `system`コールは接頭辞で `RAILS_ENV=test` を付ける  
  3. これによりRSpec実行前に自動でテスト DB が最新化され、`EnvironmentMismatchError` / `PendingMigrationError` を防止

## 学習内容5  
- **タグ**: LINEログイン  
- **タイトル**: LINEログイン実装前に関する公式ドキュメント1  
- **内容**:
[Integrating LINE Login into your web app](https://developers.line.biz/en/docs/line-login/integrate-line-login/?utm_source=chatgpt.com)の要約  
1. LINE Loginの仕組み(OAuth 2.0の認可コードフロー ＋ OpenID Connect拡張)
  - ユーザーが「LINEでログイン」ボタンを押す
  - ブラウザがLINEの認可画面（LINEが用意したログイン／同意画面）へリダイレクト
  - ユーザーが同意すると、認可コード（後でトークンに交換する短い文字列）とstate（CSRF対策用のランダム文字列）が自身のサイトのコールバックURLへ返ってくる
  - サーバー（Rails）が認可コードをアクセストークン・IDトークンに交換
  - 受け取ったIDトークンからユーザー情報（LINE ID, 名前, アイコンURLなど）を取得
  - LINE IDと合致するユーザーが自分のDBにいればログイン、いなければ新規登録してログイン完了
2. 開発者コンソールで行う設定
  - プロバイダー(何らかの商品やサービスを提供している人や会社という意味)作成
  - チャネル作成、チャネルタイプを「LINE Login」にする
  - Callback URLを「LINE Login」タブに登録（複数行OKなので開発用と本番用を両方書くことが可能）
  - ユーザーのメールアドレスへのアクセス許可をリクエストする
    - ウェブアプリでユーザーのメールアドレスを取得するには、まずLINE Developersコンソールで許可を申請
    - 利用規約に同意し、ユーザーのメールアドレスを収集することとその使用目的を説明する画面のスクリーンショットをアップロード。
3. 「LINE でログイン」ボタンを押したときに起こること
  - Web アプリに LINE ログイン ボタンを追加する場合は、[LINEログインボタンのデザインガイドライン](https://developers.line.biz/en/docs/line-login/login-button/)に従うこと。
4. 認可コードをトークンへ交換
5. Rails 側でやる実装ポイント
  - Gem omniauth-line：認可URLの生成・コールバック受信をGemが肩代わり
  - Sorceryのexternal_providers = [:line] 設定：既存のメール＋パスワード方式と並列でLINE認証を扱う
  - Usersテーブルにprovider, uid追加：provider='line', uid='<LINEのuserId>' を保存してユーザーを一意に判定
  - SessionsControllerのlineアクション：login_from(:line) で既存ユーザーを検索、見つからなければ create_from(:line) で作成
  - 環境変数：LINE_CHANNEL_ID、LINE_CHANNEL_SECRET、LINE_REDIRECT_URI
6. 用語まとめ
  - OAuth 2.0：認可を委任するための枠組み。誰がどの情報にアクセスしていいかを決めるプロトコル
  - OpenID Connect：OAuth 2.0を「ログイン（本人確認）」用途に拡張した仕様。IDトークン（JWT）でユーザー確認
  - JWT：電子署名付きのJSON。中身を改ざんすると署名検証でバレる
  - Scope：どの情報を使わせてもらうかの一覧（profile, emailなど）
  - State：CSRF対策。最初に送ったランダム文字列と戻りの文字列が一致するか確認
  - Redirect URI：認可後に戻ってくる先のURL（コールバック）
