# ブロック、Proc、Lambda

### メソッド内でのブロック呼び出し

- block.yield、yield、block.callが可能
- yield.callは不可なので注意

### proc,lambda

- 定義の仕方
- proc
- Proc.new { |a, b| [a, b] }
- proc { |a, b| [a, b] }
- lambda
  - lambda { |a, b| [a, b] }
  - ->(a, b) { [a, b] }
- 呼び出し方(共通)
  - .call
  - .yield
  - []
  - .()
  - ===
  - callやyieldの後ろに引数をつける、ブロックを格納した変数の後につけないこと
- returnした時
  - proc: メソッドごと処理を終了する
  - lambda: そのブロックだけを終了しメソッドの処理を続ける

# 継承、Mixin

### 特異クラスの継承

- クラス継承の際に特異クラスも継承されるか
  - クラスCはクラスDの子（c < d）の場合
    - クラスC自身の特異クラスの親は、元のクラスの親Dの特異クラス。
    - 特異メソッドを継承
  - クラス（モジュール）CがモジュールDをMixinしている場合（include、extend）
    - Cの親はDだが、クラスC自身の特異クラスの親はDとならない
    - 特異メソッドは継承しない
  - クラスメソッド探索では**<span style="color: red;">c < dだけ探索してMixinは探索しないので注意</span>**
- 上記どちらの場合であっても（Cはクラス）
  - クラスCのインスタンスの特異クラスの親は、元のクラスC
  - CとCの特異クラスが親子になることはない

### スコープ内とスコープ外に同じ名前のクラスがあり継承する場合

- クラス名は定数なのでレキシカルスコープから優先的に探索
- ただしスコープ内であっても親とするクラスが下に記述がある場合は無視される。

### included append_features

- includeした瞬間に勝手に動くので自分からM.append_featuresと呼び出す必要はない
- `class C; include M; end`と書いた瞬間に、Rubyの内部で以下の順に実行。
  - M.append_features(C) が呼ばれる（継承していいかのチェックなどに向く）
  - 継承
  - M.included(C) が呼ばれる（事後処理）
- append_featuresはincludeの実態なのでメソッド内でsuperを呼ばないと、includeしても継承リストへの追加が行われない。
- includeは通常インスタンスメソッドしか追加できないが、includedの中でクラスメソッドを自動追加することが可能
  - includedで引数(base)を受け取りその中でメソッド「def base.~~~」と定義
  - append_featuresでも可能だがincludedでするのが普通
- 他にも「prepend_features prepended」と「extend_object extended」がある

### 他

- obj.extend(Mixin)のようにextendは任意のオブジェクトに対して使える

# 探索

### クラス変数の探索

- ネストは見に行かず自分のクラスとその継承関係だけを探す。
  - CとCの特異クラスが親子になることはないが、継承クラスに加え特異クラスも含め同一族としクラス変数を共有する
    - Cに定義したクラス変数が`C.class_variables`でも`C.singleton_class.class_variables`でも確認できる。
  - `class << C`のように特異クラスに入ってる場合、Cの特異クラスからではなく外のクラスを基準に探索する
    - `class << C.new`としても親のCを見に行かない（定数の場合は見に行く）
- `if Child < Parent; @@val += 25`とあった場合、ifのところはクラス定義じゃないのでChildクラスを探索するのではなくifが書かれてるクラスを見る

### メソッド探索

- 親を探しに行ってメソッドを見つけ、そこで新たなメソッドを呼び出す場合は、そこのクラスからではなく最初のクラスから探索を始める
- includeA,Bとした場合、定数はAからBを見つけられないが、メソッドはAからBを見つけられる

### 定数探索

- メソッド内で定義されているからといってレシーバのクラスから探すと言ったようなルールはない
  - selfはそうだがそれとは関係ない
- `class << C.new`のように特異クラスに入ってる場合、クラス変数と違いC.newの親（C）を見に行く
  - ただしネストの後の探索
  - C.newの特異クラスは親がCで見に行けるがCの特異クラスからは無理
- CがNとMをincludeしていてどっちも同じクラス変数を定義していると、一族でクラス変数が重複してるので参照するとエラー
- includeA,Bとした場合、メソッドはAからBを見つけられるが定数はAからBを見つけられない
- const_getの定数探索
  - selfを見に行き、なければそこから継承を辿る
- メソッド内で定数直接代入 (CONST = 1)はSyntaxError
  - const_setを使えばメソッド内でも可
- `m = Module.new`とすると他クラスでincludeする際スコープ外で利用できない、大文字で定義すればOK

### メソッドの大文字定義

- エラーではない（非推奨）
- メソッド名指定だけでは呼ぶことができず、selfか()をつける必要がある（この場合定数と競合しても優先）

# 正規表現

### 正規表現を使った真偽値等の判定

- `=~`: マッチした位置を返す
  - 左辺右辺を問わない
- `match?`: 真偽値を返す
  - $1や$~を一切書き換えない
- `match`: マッチオブジェクトかnilを返す
- `str.include?`: 引数に正規表現を引数に取ることはできない
- contentやcontainsというメソッドはない

### Regepex

- 特殊変数
  - マッチ系(`"Ruby31" =~ /([a-z]+)(\d+)/i`を例にする)
    - $~ : #<MatchData "Ruby31" 1:"Ruby" 2:"31">（マッチデータ全体）
    - $& : "Ruby31"（最後にマッチした文字列）
    - $1 : "Ruby"（1番目のカッコ）
    - $2 : "31"（2番目のカッコ）
    - $+ : "31"（最後のカッコ）
    - $` : ""（最後にマッチした文字列、今回でいう"Ruby31"の手前の文字列）
    - $' : ""（最後にマッチした文字列、今回でいう"Ruby31"の後ろの文字列）
  - 例外系
    - $! : 最後に発生した例外オブジェクト
    - $@ : 最後に発生した例外のバックトレース
    - $0 : コマンドライン引数で指定したファイル名、現在実行中のファイル名
    - $\* : ARGV、スクリプトに渡されたコマンドライン引数の配列
  - $: : $LOAD_PATH、ライブラリを検索するディレクトリのパスを保持する配列
  - $\_ : getsかreadlinesで最後に取得したもの
- `[]`
  - 中に含むいずれかの1文字にマッチせよという意味
  - `[]`の中では`|`, `.`, `*`, `+`, `?`, `()`, `{}`はただの文字として扱われる。
  - `\`, `[]`, `-`は意味を持つのでエスケープが必要
  - `^`は先頭にある場合のみ意味を持つ
  - `/[^a-z ]+/`は「小文字じゃない、またはスペース」ではなく「小文字でもスペースでもない」
- `+`や`*`といった繰り返しは基本的にできるだけ長くとってマッチしようとする
  - `"Ruby-3.1"[/[A-Z].*[-.]\d/]`の`.*`はできるだけ長く取ろうとするので、`Ruby-3`ではなく`Ruby-3.1`となる
  - `+?`や`*?`にするとできるだけ短く取ろうとする
    - `<div><span></span></div>`だと`<div>`にマッチ

# method_missingとconst_missing

### method_missing

- クラスCで`def method_missing(id, *args)`して`C.dummy_method`しても呼ばれない
  - 対応してるのは`C.new.dummy_method`

### method_missingとrespond_to？とrespond_to_missing?

- `g.respond_to?(:say_hello)`のようにしてメソッドを持つか確認できる
- `respond_to?`はオーバーライドせず代わりに`respond_to_missing?`を定義する
  - method_missingで「こういうメソッド名の場合はこういう処理にする」と擬似的にメソッド定義した場合によく使われる
  - これにより擬似的なメソッドが`respond_to?`でtrueを返したり、methodメソッドとcallメソッドの組み合わせで呼べるようになったりする

### const_missing

- クラスメソッドとして定義
- 定数をレキシカルスコープ、継承の順で探索し他あとconst_missingを継承順で探索

# private,protected,public

### private

- 子クラスから丸見え
  - superで呼べる
  - メソッド名指定で呼べる
  - privateにself.some_methodと(クラスメソッド定義)してもpublicになる
- privateをself.some_methodと呼べるがクラス名.some_methodはクラスメソッド呼ぶのでprivate呼べない

### protected

- 同じクラス（または継承関係）の「他のインスタンス」からでも呼べる。
  - otherを引数で受け取り`other.protected_method`のように使える

### 子クラスで親のメソッドをprivateにしたりpublicにしたりする

- 子で変更しても子だけ変更される
- 親で変更すると親も変更される（子クラス定義後の変更でも）

# Time,Datetime,Date

## Time→String

### Timeインスタンス.strftime(書式の文字列) => String

- 記号の意味
  - %F 日付 (ISO 8601形式) Full date 2024-03-23
  - %D 米国式日付 (月/日/年) Date (US) 03/23/24
  - %T 時刻 (24時間) Time 15:30:45
  - %R 時刻 (時:分) Relax (秒なし) 15:30
  - %u: 曜日 (月曜=1, 日曜=7) ※数字で出るのがポイント。
  - %z: タイムゾーン (+0900)。
  - %Z: タイムゾーン名。
- 紛らわしいやつ
  - `time_object.strftime("%F %T") => "2024-03-23 15:30:45"`
  - (間にスペースがあり、タイムゾーンがない)
- strftimeはTimeクラスの標準メソッドなので、`require 'time'`が不要

### Timeインスタンス.iso8601 => String

- Time.iso8601(文字列) => Time については後述
- `time_object.iso8601 => "2024-03-23T15:30:45+09:00"`のような形式で文字列出力
  - 年月日は`-`で繋ぐ
  - 時間は`:`で繋ぐ
  - 時間の手前に`T`
  - タイムゾーンは`+09:00"`のような形式、もしくは`Z`

## String→Time

### Time.parse(文字列) → Time

### Time.strptime(文字列, フォーマット文字列) → Time

- ブロックを渡すとブロック引数で年数を返す（`%Y`は4桁、`%y`は2桁）、値を編集できる
  - `Time.strptime('91/5/18 4:13:00', '%Y/%m/%d %T')`は0091年になる
  - 1900を足したり2000を足したりする処理をブロックで書く

### `Time.iso8601(文字列)` → Time

- `Time.iso8601("2024-03-23T15:30:45+09:00")`のようにするとTimeオブジェクトを生成する。

## 備考

- 上記のメソッドはstrftimeを除いて`require 'time'`必須
- Dateも上記と同様のメソッドあり、違いは以下の通り
  - Date使う時点でrequireはマスト
  - さらに`Date._parse(文字列)`もある、戻り値がハッシュ

### returnとbreak

- returnはメソッドそのものを抜けるがbreakは一つのループ（ブロック）しか抜けない

# Karnel

### `Kernel.#caller`

- プログラムのどこを十個空いているかという履歴を返す
- 戻り値は「文字列(String)の配列」

### Kernelメソッドとして存在するか

- 存在する: Integer, Float, Array, Hash, String, Rational, Complex
  - Integer("100")等でインスタンス生成可能
  - ただしto_i等より厳格で`Integer("10abc")`のように余分なものがあるとArgumentError
- 存在しない： Time, Date, File, Dir
  - Time("2024-01-01")等はNoMethodError

### undef(undef_method)とremove_method（クラスCとC子とC親を例にする）

- undefとundef_methodは呼び出し方以外同じ挙動
  - undefはdefのような書き方、undef_methodとremove_methodはシンボルか文字列
- undefは定義を消した上に親に対する呼び出しも封印、remove_methodは定義してなかったことにするだけ
  - undefはC親のも見えなくなり、remove_methodはC親のが見える
    - undefでもC親から消すわけではない
  - undefもremove_methodもC子からは利用できなくなる
  - undefはC子からもC親のが見えなくなり、remove_methodはC子からC親のが見える
- undef後にメソッドを再定義した場合は呼び出し可能

### dig

- ハッシュや配列のネストに対し「どのキーの何番目の何番目のどのキーの・・・」と言ったように探索ができる。
- `data[:users][99][:name] `のようにして見つからない場合NoMethodErrorだが`data.dig(:users, 99, :name)`ならnil
- 配列やハッシュにしか使えないのでそれ以外のオブジェクトからさらに中を探索しようとするとTypeError
- 存在しないキーや番号から突き進んでもエラーではなくnil

### rubyコマンドのオプション

  - s(script): スクリプト引数をグローバル変数として扱う。???

### case whenとcase in

- 「AまたはBまたはCに該当」
  - when: `,`で区切る
  - in: `|`で区切る
- 一致するwhenやinがないとき
  - when: nilが返る
  - in: 例外
- ハッシュ同士を比較
  - whenもinも内容が完全に一致するかを判定する
- case when限定
  - `===`で比較している
  - `case A; when B`だったら`B === A`で判定

### ENV

- `ENV['aaa'] = 'aaa/bbb/ccc'`とハッシュのように扱う

### `$0`と`__FILE__`

- いずれもファイル名を指す
  - `$0`: 実行時に指定したパス（つまりメインのファイルパス）の文字列がそのまま入る（相対パスで呼べば相対パス）。
  - `__FILE__`: その記述があるファイルの場所を指す。
  - `require`された時は一致しない
- `$0`は代入可能
- `$0`には`$PROGRAM_NAME`という別名がある。

### squeeze

- 文字列に対し使い連続した同文字を1文字にする
- 引数を与えないと連続した全ての文字が対象
  - 特定の文字を引数に指定することも可能、ただし`,`で区切って複数指定は不可
  - 引数複数文字指定1: `("aedcb")`のようにする、a,b,c,d,e五文字を対象にする。
  - 引数複数文字指定2: `("a-e")`のようにすると指定した範囲の文字を対象にすることができる
  - 引数複数文字指定3: `^f`とするとf以外を対象というように指定できる

### to_str

- to_s: 全オブジェクトが持っていて「とりあえず文字列にして人間が見る用」にする。
- to_str: 「お前はもう実質文字列だよね？」っていうごく一部の連中しか使えない(StringやException)。
- Kernel#putsは引数にto_sを呼ぶ（to_strだったら対応しないオブジェクトだらけで困る）
- Kernel#pも引数にto_sを呼ぶ（to_strだったら対応しないオブジェクトだらけで困る）
- to_str は String のように振る舞えるオブジェクトのみ実装すべき（◯ 正解）
