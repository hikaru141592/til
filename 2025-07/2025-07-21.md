## 学習内容1  
- **タグ**: プッシュ通知, Webhook
- **タイトル**: LINE MessagingAPIのWebhook
- **内容**: 
LINEプッシュ通知機能に関して、ユーザーがLINE友達追加を行ったか行ってないかをアプリ側で管理できるようWebhookを利用する。以下、それに関するメモ。
  - 友だち追加やユーザーからのメッセージ送信のようなイベントが発生すると、LINEプラットフォームからWebhook URL（ボットサーバー、チャンネルごとにURLを設定）にHTTPS POSTリクエストが送信される。
  - イベント処理を非同期化することが推奨される。
    - HTTP POSTリクエストの処理が後続のイベントの処理に遅延を与えないようにする。
    - 「イベント処理を非同期化する」とは、LINEから届いたWebhookのPOSTリクエストを受け取ってからすぐにHTTP 200を返し、その後で実際のメッセージ解析やDB更新、API呼び出しなどの重たい処理を、別のプロセス（＝バックグラウンドジョブ）に投げて実行するということ。
    - LINEではWebhookに対して5秒以内に200OKを返さないと、失敗とみなして再送（リトライ）してくるので、処理が遅いと同じイベントが何度も飛んできてしまう。
    - 同時に大量のイベントが来ても、Webサーバーは受信・即レスポンスだけに専念しジョブキューに溜めて順次さばくことで安定動作しやすくなる。
    - イベント処理を非同期化のためには、本来リクエスト処理に専念するWebコンテナと、別のプロセス（＝バックグラウンドジョブ）をこなすWorkerコンテナに分けることが望ましいが、Herokuの場合dynoが追加で必要になりbasicプラン1つ分から2つ分を要することになる。
    - ポートフォリオでは、WebコンテナWorkerコンテナに分けなくてはいけないほどの大量のリクエストは想定されないので、Active Jobのasyncアダプタを使うこととする。
      - Railsにはデフォルトでasyncという非同期実行用アダプタが入っている。
        - Web Dyno（Puma）上の スレッドプールでジョブをバックグラウンド実行、別Dynoを立てずにバックグラウンドジョブ並行処理が可能。
        - Rails7ならGem設定不要でそのまま使用可能。
        - config/application.rbに`config.active_job.queue_adapter = :async`を追記する（デフォルトで`:async`のはずだが、明示的に指定しておくと安心）。
    - LINEはWebhookリクエスト送信元のLINEプラットフォームのIPアドレスは開示していないので、セキュリティの担保はIPアドレスのリストによるアクセス制御ではなく、署名の検証で実施しなくてはならない（コントローラーにて処理）。
      - 署名検証は必ずすること。
      - 後述のリクエストヘッダーのx-line-signatureに署名がセットされる（HMAC-SHA256で署名生成される）。
      - 受信したWebhookのリクエストボディの文字列を入力データ、ボットサーバで管理していたチャネルシークレットをハッシュ鍵としてHMAC-SHA256で署名を生成、それと受信した署名（x-line-signature）を比較し検証。署名が一致した場合、受信したWebhookはLINEプラットフォームから送信され、改ざんされることなくボットサーバーに到達したものであることが保証される。
    - リクエストヘッダー
      - x-line-signature（ヘッダーフィールド名の大文字小文字を区別せずに扱うこと、通常区別されないので気にしなくて大丈夫だが）
    - リクエストボディ（Webhookイベントを受信すべきボットのユーザーIDとWebhookイベントオブジェクトの配列を含むJSONオブジェクトで構成）
      - destination: Webhookイベントを受信すべきボットのユーザーID（ユーザーIDの値は、U[0-9a-f]{32}の正規表現にマッチする文字列）。
      - events     : Webhookイベントオブジェクトの配列。LINEプラットフォームからの疎通確認のために、Webhookイベントオブジェクトを含まない空配列が送信される場合もある。
    - レスポンス
      - LINEプラットフォームから送信されるHTTP POSTリクエストをボットサーバーで受信したときは、ステータスコード200を返すようにすること
      - LINEプラットフォームから疎通確認のために、Webhookイベントが含まれないHTTP POSTリクエストが送信されることがあるが、その場合も、ステータスコード200を返すこと。
      ```
      # Webhookイベントが含まれないHTTP POSTリクエストの例
      {
        "destination": "xxxxxxxxxx",
        "events": []
      }
      ```
