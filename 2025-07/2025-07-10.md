## 学習内容1  
- **タグ**: Rails, PostgreSQL, JSONB, データ設計
- **タイトル**: 既存のtext型カラムにJSONBサブカラムを追加して例外的な複数メッセージ対応を実現  
- **内容**: 
cutsテーブルにはmessageというtext型のカラムがある。開発途中で、一つのcutに対し複数のmessageを登録したくなった（基本は一つしか必要ないが、ほぼ例外的にあるcutに対し複数のmessageが必要になった）。そこで4つの案を検討した。。
  1. 既存の一つのtext型のmessageに、区切り文字を用いて強引に複数のmessageを登録する。
    - メッセージ内に区切り文字が混入するだけで壊れる、要素ごとにバリデーションやメタ情報を付けにくい、将来検索や編集UIを作るようになった場合等に手間が増大するので望ましくない
  2. 別テーブルを作成する
    - 一番きれいではあるが、すでにデータ作成がかなり進んでおり、新しいテーブルへ保存しなおすのが大変なので今回は見送り
  3. messageをtext型からJSONB型にする
    - 2と同様でデータ再作成が手間なので見送り
  4. 既存text型messageカラムに加え、サブとしてJSONB型のカラムを作成
    - 既存データに影響を与えず、安全に追加できるため今回はこれを採用

## 学習内容2  
- **タグ**: Ruby, Array
- **タイトル**: `Array#sample` によるランダム抽出と関連メソッド・乱数制御まとめ  
- **内容**:  
Rubyの`Array#sample`は配列から要素をランダムに取り出すメソッド。引数なしで１要素を返し、引数に数値`n`を渡すと重複なく`n`個の要素を配列で返す。
  1. 基本構文  
     ```
     fruits = %w[apple banana cherry date]
     fruits.sample        # "banana"など１要素 (String)
     fruits.sample(2)     # ["date", "apple"]など２要素 (Array)
     ```  
  2. 破壊的でない  
     - `sample`は元の配列を変更しない（非破壊的）。  
  3. `shuffle`との違い  
     - `array.shuffle.first(n)` と同等の結果を返すが、`shuffle`は全要素をランダムに並び替えてから切り出すのに対し、`sample`は必要な分だけランダム抽出するので大きな配列では若干効率的。  
  4. **Enumerable#sample**  
     - `Array`だけでなく、`Set`や`Hash#keys`にも使える（`Enumerable`をincludeしているクラス全般）。
