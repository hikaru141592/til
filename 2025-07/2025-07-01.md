## 学習内容1  
- **タグ**: Rspec
- **タイトル**: テストで日時を固定する
- **内容**:  
`ActiveSupport::Testing::TimeHelpers`モジュールを用いるとRailsのテストやRSpecで現在時刻を自由にコントロールし、任意の日付や時刻でコードを実行・検証することができる。

### セットアップ
- spec/rails_helper.rbなどで以下を追加
```
    RSpec.configure do |config|
      config.include ActiveSupport::Testing::TimeHelpers
    end
```
これにより`travel_to`や`travel_back`が使えるように。

### travel_to
- ブロック内の時刻をモックする
```
    travel_to(Time.zone.local(2025, 6, 30, 19, 0)) do
      # この中では Time.zone.now が 2025-06-30 19:00 に固定
      expect(Time.zone.now.hour).to eq 19
    end    
    # ブロックを抜けると元の実時間に戻る
```

### travel_back
手動でモックを解除したい場合に使用

### 複数のテストで時間設定を使いまわす
RSpecの`around`フックでまとめることも可能。spec/rails_helper.rbなどで以下のようにする。
```
    config.around(:each, :time_travel) do |example|
      travel_to Time.zone.local(2025,6,30,0,0)
      example.run
      travel_back
    end
```
各テスト作成時は以下のようにする。今回の例では**time_travel**が設定されてるもののみ有効。
```
RSpec.describe SomeService, type: :service do
  it '通常のテスト（設定は影響なし）' do
    # travel_toは作用しない
    expect(Time.zone.now).not_to eq Time.zone.local(2025,6,30)
  end

  it 'time_travelを使いたいテスト', time_travel do
    # この中ではtravel_toが効く
    expect(Time.zone.now).to eq Time.zone.local(2025,6,30,0,0)
  end
```

## 学習内容2  
- **タグ**: Heroku, ネットワーク, エラー
- **タイトル**: Heroku runでETIMEDOUT
- **内容**: 
- 事象
  - 'Heroku run'でETIMEDOUTというエラーになった。
  - 最初seedの投入で失敗したのだが'-- echo "Hello, Heroku!'等でも失敗したため環境の問題と考えられる。
  - ネットワーク接続をポケットWi-Fiからスマホのテザリングに切り替えたところで解決
- 考えられる原因
  - ポケットWi-Fi環境ではタイムアウトが発生し、スマホのテザリングではうまくいった理由として、主に以下のようなネットワークの違いが考えられる。
      - NAT/ファイアウォールの挙動: ポケットWi-Fiは小型ルーターで、内蔵のNAT（ネットワークアドレス変換）やファイアウォールが比較的厳しく設定されている場合がある。Heroku CLIはDyno（Heroku 上の一時コンテナ）と“常時接続”で標準入出力をストリーミングする方式を使うが、途中でNATテーブルからセッション情報が消えると接続が切断され、タイムアウトになる。
      - アイドルタイムアウト時間の差: ポケットWi-Fiの多くは省電力やコスト節約のために、一定時間データのやり取りがないとTCPセッションを切断する（アイドルタイムアウトが短い）。スマホのテザリングでは、キャリアのセルラー網を経由するため、アイドルタイムアウトが長めに設定されており、長時間のストリーミング接続でも切れにくい傾向がある。
      - 通信品質・帯域幅の違い: ポケットWi-Fiは同時接続数や通信量に制限があることが多く、パケットロスや通信遅延が発生しやすい。スマホ回線では通常、セルラー網内での通信が優先され、比較的安定した速度・遅延で接続が維持されやすい。
