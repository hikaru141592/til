- **タグ**: Rails, RESTful, ルーティング
- **タイトル**: RailsのRESTfulルーティング
- **内容**: 
### RESTとは
  - "リソース（資源）"をURIで一意に表し、HTTPメソッド（動詞）で操作する設計思想。
  - Railsでは「コントローラ＋アクション」をリソース指向でマッピングし、ルーティングをシンプルに保つ。

  | CRUD   | HTTP 動詞                | Rails アクション        | 目的        |
  | ------ | ---------------------- | ------------------ | --------- |
  | Create | **POST**               | `#create`          | 新規作成      |
  | Read   | **GET**                | `#index` / `#show` | 一覧 / 詳細表示 |
  | Update | **PATCH** (or **PUT**) | `#update`          | 更新        |
  | Delete | **DELETE**             | `#destroy`         | 削除        |

  > **PATCHとPUT**: Rails7では部分更新はPATCH、全置換はPUT。

### resourcesでフルセットを生成

  ```
  # config/routes.rb
  resources :articles
  ```

  `rails routes` 実行結果（省略許可）

  | Helper                   | Verb      | Path                | Controller#Action | CRUD |
  | ------------------------ | --------- | ------------------- | ----------------- | ---- |
  | `articles_path`          | GET       | /articles           | articles#index    | R    |
  | `new_article_path`       | GET       | /articles/new       | articles#new      | R    |
  | `article_path(:id)`      | GET       | /articles/\:id      | articles#show     | R    |
  | *(collection)*           | POST      | /articles           | articles#create   | C    |
  | `edit_article_path(:id)` | GET       | /articles/\:id/edit | articles#edit     | R    |
  | *(member)*               | PATCH/PUT | /articles/\:id      | articles#update   | U    |
  | *(member)*               | DELETE    | /articles/\:id      | articles#destroy  | D    |

  #### 必要なルートだけ生成

  ```rb
  resources :articles, only: %i[index show]
  resources :comments, except: %i[new edit]
  ```

### resource（単数形）
  - ユーザープロフィールなどID不要で常に1件の場合。
  ```
  resource :profile, only: %i[show edit update]
  # /profile (単数) のみ生成
  ```

### ネストされたリソース
```rb
resources :articles do
  resources :comments, only: %i[create destroy]
end
# /articles/:article_id/comments/:idとなる
```
  #### シャロー（浅い）ネスト
  - 深すぎるURLを防ぐ。
  ```
  resources :articles, shallow: true do
    resources :comments
  end
  ```
  - 生成例:`/comments/:id`で単独アクセス可。

### 非RESTfulルートについて
  - 基本は`resources`で表現できる設計にする。
  - どうしても必要な場合のみ`get`,`post`,`match`を直接使用。

## 学習内容2 
- **タグ**: モーダル
- **タイトル**: モーダルとフォーカス管理
- **内容**:
### モーダルとは
  - 背景を覆って前面に浮かぶUIコンポーネント。
  - ユーザーがモーダルを閉じるまで、アプリケーションの他の部分と対話できない。
### アクセシビリティの要件
  - ARIA属性を使い、支援技術にモーダルの存在と状態を伝える。
    - `role="dialog"`または`role="alertdialog"`を設定
    - `aria-modal="true"`で背景の操作を無効化
    - `aria-labelledby`/`aria-describedby`でラベルと説明を指定
### フォーカス管理の基本
  1. 開いたときの初期フォーカスをモーダル内の最初の操作可能要素に移動
  2. フォーカストラップ (focus trap)を実装し、タブ鍵で外に出ないように制限
  3. 閉じたときのフォーカス返却を、開く前にフォーカスしていた要素へ戻す

- **タイトル**: モーダル実装で学んだこと 
- **内容**:
### 1. Stimulusの基礎
| 覚えたこと | メモ |
|------------|-------------------|
| **ファイル名とdata-controllerの対応**<br>`status_controller.js` → `data-controller="status"` | 名前さえ合っていれば自動リンク。 |
| **targets**<br>`static targets = ["modal", "frame"]` → `data-status-target="modal"` 等 | controllerを付けた要素配下に必ずtargetを置く。 |
| **action**<br>`data-action="click->status#open"` | クリックした要素から親方向にcontrollerがないと発火しない。 |
### 2. Bootstrapとimportmap
| 覚えたこと | メモ |
|------------|-------------------|
| UMD版とESM版 | `bootstrap.bundle.min.js` はUMD。`import { Modal } from "bootstrap"`は不可。 |
| UMD版での呼び出し方 | `import "bootstrap"` → `bootstrap.Modal.getOrCreateInstance(element)` |
| ESM版を使う場合 | `pin "bootstrap", to: "bootstrap.esm.js"`に差し替えてから`import { Modal }`。 |
### 3. モーダルをJSから開く
```
const modal = bootstrap.Modal.getOrCreateInstance(el) // UMD版
modal.show()
```
  1. <div class="modal fade"> をDOMに置く
  2. JSでインスタンス化 → `.show()`
