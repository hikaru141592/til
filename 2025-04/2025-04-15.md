## 学習内容1
- **タグ**: git
- **タイトル**: git reset --soft HEAD~1
- **内容**:
直前のコミットを取り消す、ただし作業ディレクトリとインデックス（ステージ）には何も触らない。
git reset --soft HEAD~1
　→ HEAD（現在のブランチのポインタ）だけを動かす、ステージング（インデックス）や作業ツリー（ファイルの状態）は変更しない(つまりaddは残ったまま)。
HEAD~1　→ 1つ前のコミット、つまり直前のコミットを指す。
--softを--mixedにするとステージング（インデックス）も初期化され(addしてない状態に)、
--hardとすると作業ツリー（ファイルの状態）も巻き戻される。
commitのコメントを修正したいだけのとき等はgit reset --soft HEAD~1とするのが良い。

## 学習内容3
- **タグ**: プロジェクト,アジャイル開発
- **タイトル**: アジャイル開発におけるストーリーポイント
- **内容**:
ストーリーポイント
アジャイル開発ではタスクの複雑さや労力を測定するために、ストーリーポイントと呼ばれる相対的な単位を使用する。
通常は1～13までのフィボナッチ数が使われるが、とりあえずは1,2,3のみの使用に留める。
安見積もり時間
1：修正や簡単な修正レベルのタスク
2：バグ修正や簡単な機能追加レベルのタスク
3：実装が想像できる通常の機能レベルのタスク
RUNTEQにおいては作業の目安時間としてストーリーポイントx2時間を提示しているが、開発を進めていくなかで目安時間が異なる場合は、自身の経験に基づいて適宜修正して見積もりを行う。

## 学習内容4
- **タグ**: プロジェクト,アジャイル開発,Github
- **タイトル**: アジャイル開発におけるストーリーポイント
- **内容**:
プルリクエストとIssueをリンクするには、プルリクエストの説明欄に以下のような記載を入れる。
```
closes #10
```
こうすることで、このPRはIssue番号10番の課題を解決することを意味し、マージしたら自動でIssue #10を閉じてくれる。
(closes以外にもいろんなキーワード有り)。
また他のリポジトリのIssueを閉じたい時は、
```
closes ユーザー名/リポジトリ名#Issue番号
```
とする。
また、
PRの画面から手動でリンクする：対象のPull Requestを開き、右側の「開発（Development）」っていう欄からリンクしたいIssueを選ぶ
Issueの画面から手動でリンクする：対象のIssueを開き、右側の「開発（Development）」をクリック、リンクしたいPRやブランチを選んで適用
とすることも可能。

## 学習内容5
- **タグ**: テスト
- **タイトル**: CI/CD
- **内容**:
CI：Continuous Integration（継続的インテグレーション）の略、コードがちゃんと動くか自動でチェックする。
CD：Continuous Deployment/Delivery（継続的デリバリー／デプロイ）の略、テストに通ったら自動でサーバーに反映（デプロイ）する。
CI/CDのイメージ：コードを書く→GitHubにpush→自動でテストが走る（CI）→問題なければ自動で本番環境にデプロイ（CD）→これをCI/CDツール（例：GitHub Actions、CircleCI、GitLab CI）がやってくれる。

## 学習内容7
- **タグ**: HTML
- **タイトル**: メタタグ
- **内容**:
HTMLの <head> タグの中に書くそのページに関する情報（メタ情報）のこと。
ページの見た目に影響されないが、検索エンジンやSNSにページがどんなページであるかを伝える役割を持っている。
例：
```
<meta charset="UTF-8"> <!-- 文字コードを指定 -->
<meta name="description" content="キャラクター育成ゲームの紹介ページです">
<meta name="keywords" content="育成ゲーム, Rails, ポートフォリオ">
<meta name="author" content="あなたの名前">
<meta name="viewport" content="width=device-width, initial-scale=1.0">
```
※Railsでは「meta-tags」gemが便利

## 学習内容9
- **タグ**: 検索エンジン
- **タイトル**: Google Search Consoleについて
- **内容**:
Google検索エンジンにおいて自分のWebサイトがどのように検索結果に表示されているかを把握し、改善するためのサービス。
Google Search Consoleに自分のWebサイトを登録することで、以下のようなことができるようになる。
①Googleに自分のWebサイトを認識させることができる。
②検索クエリーで表示される自分のWebサイトの順位やクリック数を確認できる
③自分のWebサイトに対するクロールエラーやスパムリンクなどの問題を把握できる
※GoogleにはGooglebotという自動ロボットのようなものがいて世界中のWebサイトを毎日ひたすら巡回している、これをクロールという。
④自分のWebサイトのサイトマップを提出することでクロールの効率を上げることができる(クロールが自分のWebサイトをみつけやすくなる)。
※サイトマップ（sitemap.xml）にはWebサイトのURL、最終更新日、更新頻度、プライオリティ(重要度)等を記載できる、またRailsではSitemapGeneratorを使うことで手軽にサイトマップを作製できる。

## 学習内容12
- **タグ**: テスト
- **タイトル**: SimpleCovについて
- **内容**:
SimpleCov(シンプルカブ)はテストでどこまでコードがチェックされているかを教えてくれるGem。
テストを実行するとテストされた行は緑で表示され、テストされてない行は赤で表示される。
また全体のカバー率も確認可能。
ちなみにカバレッジとはどれくらいテストでコードをチェックできてるかの割合のこと。
