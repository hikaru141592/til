## 学習内容1
- **タグ**: whenever,cron
- **タイトル**: wheneverとは
- **内容**:
wheneverは、cronの設定をRubyコード（DSL）で簡単に書けるようにするGem。
crontabは慣れてないと読みにくくて書きづらいが、wheneverはRubyコードで定期実行の設定を書けるので、Railsアプリとの相性が良い。
wheneverは、Railsのコード（schedule.rb）を使ってcrontab（cronの設定ファイル）を自動で作るだけのGemなので
一度 wheneverを使ってcrontabを生成したら、その後はwhenever自体は使わないでもcronは動き続ける。
そのため
```
gem 'whenever', require: false
```
としてよい。

## 学習内容2
- **タグ**: whenever,cron
- **タイトル**: wheneverの使い方
- **内容**:
①
```
gem 'whenever', require: false
```
をGemfileに記述。
通常はGemfileに書いたGemは自動でrequireされるがrequire: falseによりRails起動時にそのGemを読み込まないようにできる。
wheneverは開発時に使うだけ（本番環境ではcronに変換してしまえば不要）、Rails本体の起動には不要でありメモリ節約のため読み込まない。
②
```
bundle exec wheneverize .
```
で初期設定ファイルを作成しconfig/schedule.rbに以下のように定期実行の処理を書く。
```
every 1.day, at: '7:00 am' do
  runner "DailyReportMailer.send_report.deliver_now"
end
```
※runnerはRailsアプリの中のコードをコマンドラインで実行するためのコマンド
③
実際のcronに反映する
```
whenever --update-crontab
```

## 学習内容3
- **タグ**: whenever,cron
- **タイトル**: dockerでwheneverを使う場合
- **内容**:
①
Dockerfileにcronを追加、より具体的には、
```
RUN apt-get update -qq && apt-get install -y build-essential libpq-dev nodejs cron
```
を追加しcronをインストール。
②
bundle exec wheneverize .
を実行しconfig/schedule.rbを作成
※config/schedule.rb(cronスケジュールを書くための設定ファイル)とconfig/initializers/whenever.rb(これは基本使わないので無視してOK)が作成される。
③
entrypoint.shを作ってcronとRailsを同時に起動
Dockerではコンテナ起動時に自動で実行されるスクリプトentrypoint.shを作れる。
このスクリプトの中で「cronを起動して」「Railsサーバも起動する」というふうにする。

```
# entrypoint.sh（プロジェクトルートに作成）

#!/bin/bash
# set -eは「どこかでエラーが出たらそこで止める」という意味
set -e

# コンテナが起動するたびにcrontab を更新
bundle exec whenever --update-crontab

# cron をバックグラウンドで起動
cron

# その後、Railsサーバーを起動（引数で渡されたコマンドを実行）
exec "$@"
```
※chmod +x entrypoint.sh を実行して実行権限をつけておくこと。
④
docker-compose.ymlを調整
```
services:
  web:
    build: .
    command: bash entrypoint.sh rails server -b 0.0.0.0
    volumes:
      - .:/app
    depends_on:
      - db
```
⑤
docker compose build で再ビルド、docker compose upで起動、
コンテナ内でcronが起動され、定期的にメール送信が動く。

## 学習内容4
- **タグ**: docker
- **タイトル**: docker-compose.ymlの内容について
- **内容**:
docker-compose.ymlの内容について
```
services:
  web:
    build: .
    command: bash entrypoint.sh rails server -b 0.0.0.0
    volumes:
      - .:/app
    depends_on:
      - db
```
①services
複数のサービス（アプリ・DBなど）を定義する、web, db, redis, chrome などがここに並ぶ。
Railsアプリではweb(Rails本体)、db(PostgreSQLなどのデータベース)が特に必須。
②
web
Railsアプリを動かすサービスの名前、rails_appとか好きに変えてもいい
③build: .
カレントディレクトリのDockerfileを元にイメージを作る
④command
コンテナ起動時に実行するコマンド。
※-b 0.0.0.0 は、外から（ホストPCから）アクセスできるようにするための設定で、Dockerの中だけでなくlocalhost:3000 からブラウザでアクセスできるようになる。
※rails server -b 0.0.0.0はbash entrypoint.shの引数にあたる、entrypoint.shにexec "$@"があるとそこで引数となっていたコマンドが実行。
volumes	.:/app
ホストPCのカレントディレクトリ（.）を /app にマウント、これによりホストPCのファイルをDockerコンテナの中からも見えるようにすることができる。
depends_on	db が立ち上がるのを待ってから web を起動する
※Railsアプリ（web）が先に起動しちゃうとデータベースに接続できませんエラーになる。
※depends_on は 順番は保証してくれるがデータベースの準備完了までは待ってくれないので注entrypoint.sh で「DBがつながるまでリトライ」みたいな処理を書くとより安全。

## 学習内容5
- **タグ**: docker
- **タイトル**: docker-compose.ymlとは
- **内容**:
複数のDockerコンテナを一括で定義・管理できる設定ファイル。
Railsアプリはwebサービス、dbサービス、cron（タスクスケジューラ）、JavaScriptビルド(Node.jsやWebpacker)等を必要とするが、
Dockerではそれぞれを別々のコンテナとして動かす。
しかし一つずつrunするのは大変なのでまとめてrunできるよう設定ファイルを用意する。
これによりdocker compose upだけで全部のコンテナを起動できる。

## 学習内容6
- **タグ**: ActionMailer,メール
- **タイトル**: ActionMailerとは
- **内容**:
Railsでメールを送るためのフレームワーク。
Rails7.0には最初からActionMailerが組み込まれているのでgemのインストールは不要。
使うにあたっての大まかな流れは、
①メール送信の設定をするためにconfig/environments/development.rbを編集。
②Mailerを作成するためにrails generate mailer DailyReportMailerを実行、app/mailers/daily_report_mailer.rb（メインの処理を書く）とapp/views/daily_report_mailer/（メール本文を書く）が作成される。
③app/mailers/daily_report_mailer.rbを編集しメール送信処理を記載する。
④app/views/daily_report_mailer/下に.text.erb(プレーンテキストのメール)か.html.erb(HTMLメール)ファイルを作成しメール本文を記載する。
⑤RailsコンソールでDailyReportMailer.メール本文ファイル名.deliver_nowとすることで送信テストが可能。

## 学習内容7
- **タグ**: letter_opener,メール
- **タイトル**: letter_openerとは
- **内容**:
letter_openerは、Railsでメール送信のテストやデバッグを簡単に行うためのgem。
実際にメールが送信されることなく、ブラウザにその内容を表示してくれる。
特に開発環境やテスト環境で有用。
①Gemfileに追加
Gemfileにletter_openerを追加(開発環境でのみ使いたい場合は、group :development の中に追加)。
②bundle install
③メール送信設定を変更
config/environments/development.rbで、メール設定をletter_openerを使うように変更。
```
Rails.application.configure do
  # 他の設定が続く...

  config.action_mailer.delivery_method = :letter_opener

  # 他の設定が続く...
end
```
④メール送信をテスト
これで開発環境でArticleMailer等(例：ArticleMailer.report_summary.deliver_now)を用いてメールを送信すると実際にメールは送信されず、ブラウザが立ち上がってメールの内容を表示する。
※letter_opener はあくまで開発環境専用なので本番環境では使用しないこと、本番環境で使用する場合は、実際のメール送信サービス（例えば、SendGrid や AWS SES）を使うように設定を変更する必要あり。
