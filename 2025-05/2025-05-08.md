## 学習内容1
- **タグ**: Github
- **タイトル**: GitHubのCI（継続的インテグレーション）
- **内容**:
GitHubのCI（継続的インテグレーション）とは、コードがGitHubにプッシュされるたびに自動でテストやビルドを実行して、問題がないか確認する仕組みのこと。
そのテストやビルドに失敗するとメールで通知が来る。

## 学習内容2
- **タグ**: Github
- **タイトル**: GitHub Actions
- **内容**:
GitHub Actionsは、GitHubが提供するCI/CD（継続的インテグレーション／継続的デリバリー）ツールで、コードのビルド、テスト、デプロイなどのタスクを自動化するために使用される。
GitHub Actionsを使うことで、コードがGitHubにプッシュされるたびに、指定した一連の処理（テスト、デプロイなど）を自動で実行できる。
（yaml形式で簡単な設定ファイルを作り、その中で「こういう時にテストを走らせる」「こういう環境で動かす」といった設定をする。）

## 学習内容3
- **タグ**: Git
- **タイトル**: 過去のブランチで再度作業をしたい場合
- **内容**:
修正が必要になった等、過去のブランチで再度作業をしたい場合は以下のようにする。
・`git stash`で現在の作業内容を一時的に保存（スタッシュ）、一時的に退避させる。
・前回のブランチに切り替えて作業を行い、通常通りaddとcommit、murge等をする。
・その後現在のブランチ名に戻り、`git stash pop`する。

## 学習内容4
- **タグ**: Rails
- **タイトル**: RAILS_ENVとは
- **内容**:
コマンド実行時に`RAILS_ENV=test rails spec`のように指定すると、Railsは自動でconfig/database.ymlのtest:セクションを使う。
development：開発中に使う環境
test：RSpecなどテスト実行時に使う環境
production：本番公開時に使う環境

## 学習内容5
- **タグ**: Brakeman,ImportmapAudit,Rubocop
- **タイトル**: 静的解析・リンティングツール
- **内容**:
Brakeman:コードを実行せずにソースを解析し、SQLインジェクションやXSSなどの脆弱性を検出。
Importmap Audit:Importmapで読み込むJSライブラリの脆弱性をチェック。
Rubocop:Rubyのコーディング規約に沿っていない箇所を指摘。
これらを CI（GitHub Actions） に組み込むことで、コードの脆弱性やスタイル違反を早期に発見可能。

## 学習内容6
- **タグ**: モデル
- **タイトル**: モデルファイルの主な役割
- **内容**:
モデルファイルの主な役割
バリデーション：必須入力、文字数の上限、他レコードとの重複禁止」など、保存前にデータが正しいかどうかをチェック。
アソシエーション：他モデルとの関係、has_many／belongs_to／has_one などで、他のテーブルとの関連付けを定義。
コールバック：before_validationやafter_createのように、レコードの保存前後で自動的に何か処理を走らせたいときに使用。
スコープ・クラスメソッド：よく使う検索条件をまとめたり、レコードを取得する独自メソッドを定義。
インスタンスメソッド：そのモデルのオブジェクトが持つ振る舞いをメソッドとして記述。
