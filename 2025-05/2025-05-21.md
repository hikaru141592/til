## 学習内容1  
- **タグ**: Rspec, エラー, DB  
- **タイトル**: Rspecテストのエラー対応
- **内容**:  
| 原因 (WHAT) | なぜ起こったか (WHY) | 処方箋 (HOW) |
|-------------|----------------------|--------------|
| **開発 DB をテストが直接触った** | `DATABASE_URL` を docker が上書きし、`hikaru_dev` に接続したまま RSpec を起動 | RSpec 起動コマンドで `-e DATABASE_URL=.../hikaru_test` を必ず指定 |
| **PlayState / UserStatus が残りっぱなし**<br>（System テストだけ毎回失敗） | 直前の System テストで INSERT した行を transaction では拾えない | `DatabaseCleaner.strategy = :truncation, only: %w[play_states user_statuses]` を System 用に設定 |
| **Safeguard: “remote DB 消しそう”エラー** | Cleaner が `DATABASE_URL` を “リモート” と判定 | `DatabaseCleaner.allow_remote_database_url = true` & テスト環境確認 `abort if !Rails.env.test?` |
| **“Name は既に存在します” の重複バリデーション** | seeds で固定名を入れた後、FactoryBot も同じ名前を生成 | Factory に `sequence(:name)` を追加し必ずユニークに |
| **SyntaxError: unexpected label** | Ruby は `, only:` の改行を「ラベル」と解釈 | `DatabaseCleaner.strategy = :truncation, only: %w[ ... ]` を一行に |
| **test DB 自体が無い** | `db:create` を dev 環境でしか走らせていなかった | コンテナ内で `rails db:create db:schema:load RAILS_ENV=test` を実行して schema だけ流し込む |
| **「テスト太郎」が開発 DB に残る** | 上記すべての複合事故 | test DB 分離 + クリーナ設定で解決 |
