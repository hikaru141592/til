## 学習内容1
- **タグ**: DB
- **タイトル**: 開発/テスト/本番環境それぞれによるDB設定の分け方
- **内容**:
config/database.ymlを用いて以下のようにする。
  - 開発とテスト用は同じホスト、同じポート番号でいいがデータベース名を分ける
  - 本番環境のDBはデプロイするプラットフォーム(Heroku等)で別途設定。その設定をURLとして設定する

## 学習内容2
- **タグ**: Rspec
- **タイトル**: RspecでFactorybotやMacroを使用したい場合
- **内容**:
  1. Gemfileの:development, :testグループに`gem 'factory_bot_rails'`を追記しbundle install。
  2. spec/factories/モデル名.rbファイルを作成し内容を記述
  3. spec/support/authentication_macros.rbを作成し内容を記述
  4. spec/rails_helper.rbのRSpec.configure do |config|のブロックでそれぞれinclude句を記述する(config.include AuthenticationMacrosはtypeがsystemのものとrequestのもの用意)。
    - spec/rails_helper.rbは、RSpecを起動するときにRailsアプリケーションを読み込んでテスト環境を整えるための設定ファイル。

## 学習内容3
- **タグ**: Rspec,JavaScript
- **タイトル**: driven_by(:rack_test) とJSテスト
- **内容**:
:rack_testドライバはJavaScriptを実行しないシンプルなドライバです。
JavaScript を使わない画面遷移やフォーム送信だけのテストの場合、:rack_testのほうが軽量かつ高速に動作するためselenium_chrome_headlessなどのドライバより優先して使用するのが望ましい。
システムテストで使用されdescribeブロックの直下にbefore { driven_by(:rack_test) }と書いて使用。

- **内容**:
```
RSpec.describe "ログイン", type: :request do
  let(:user)  { create(:user) }  # 必要になったときに DB に保存される
  let!(:user2){ create(:user) }  # すべての it が始まる前に必ず保存される

  it "user2のみいる" do
    expect(User.count).to eq 1
  end
end
```

## 学習内容5
- **タグ**: Rspec
- **タイトル**: EnvironmentMismatchError
- **内容**:
`ActiveRecord::EnvironmentMismatchError: You are attempting to modify a database that was last run in `development` environment. (ActiveRecord::EnvironmentMismatchError)`のEnvironmentMismatchError（環境不一致エラー）とは、Railsが「このデータベースは⾸度にどの環境用（development／test／production）としてセットアップされたか」を内部で覚えていて、現在実行している環境（Rspec実行時ならtest）と合わないと「誤って大事な開発データを消さないように」止めてくれている状態。
ar_internal_metadataテーブルという「データベースがどの環境用か」を記録する専用テーブルがあり、現在使っているtest用データベースに、以前「development 環境用」としてマークされたままの情報が残っていたりすると、Railsが「このDBはdevelopment用と認識しているが今test環境で操作しようとしている、大丈夫？」確認をしてくれる。

■ 解決の手順
1. この DBはtest環境用であるとRailsに教える
  - docker compose run --rm web bin/rails db:environment:set RAILS_ENV=test
2. テスト用DBに最新のスキーマ（構造）を反映する
  - `docker compose run --rm web bin/rails db:`
