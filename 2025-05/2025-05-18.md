## 学習内容1  
- **タグ**: DB, スキーマ  
- **タイトル**: スキーマ情報（db/schema.rb）とは  
- **内容**:  
何か？
スキーマ情報とは、データベースの「テーブル構造（テーブル名・カラム名・型・インデックスなど）」をプログラム側で一元管理するための定義です。
Rails ではマイグレーション（db/migrate のファイル）を元に、現在のスキーマを自動的にダンプしてくれるのがdb/schema.rb。
開発者同士で現在のテーブル構造を素早く共有したいときや、CI（継続的インテグレーション）環境で、マイグレーションを実行せずに一気にスキーマを再現したいとき（rails db:schema:load）や、マイグレーションファイルを大量に実行するよりもスキーマを直接読み込んだほうが高速なとき等に使用される。

## 学習内容2  
- **タグ**: DB, Seed  
- **タイトル**: Seedの各環境への反映方法  
- **内容**:  
  1. 開発環境
    - `docker compose exec web rails db:seed`
  2. 本番環境(herokuの場合)
    - `heroku run rails db:seed --app アプリ名`
  3. テスト環境
    - `docker compose exec web rails db:seed RAILS_ENV=test` としてもテスト実行時にDBがリセットされるので意味がない。
    - spec/rails_helper.rb（または spec/spec_helper.rb）に、シードを読み込む設定を追加する。
```
RSpec.configure do |config|
  # テストDBのスキーマを最新化した後にシードを読み込む
  config.before(:suite) do
    # migrate→schema:load が終わったあとのタイミングで seeds.rb を実行
    Rails.application.load_seed
  end
end
```

## 学習内容3  
- **タグ**: DB, Seed  
- **タイトル**: 投入したシードデータを取り消す方法  
- **内容**:  
Railsのシードはマイグレーションのように自動ロールバックできるわけではない。
コンソール上で、特定テーブルのシードをまるごと消す（EventCategory.delete_all）、すべてのテーブルをドロップ（rails db:reset）等の必要あり。

## 学習内容4  
- **タグ**: アセット  
- **タイトル**: Rails8における画像のアセット  
- **内容**:
画像はRailsのアセットパイプライン（Rails8ではPropshaftがデフォルトで導入）を使って配信する。
app/assets/images以下に置くと、image_tag 'characters/tamago.png'のようにパス指定可能。
サブディレクトリを分けることで種類ごとに管理しやすくなる。
Docker／Heroku環境でも、デプロイ時に自動でassets:precompileが走るようになっていて、追加のgem等設定は不要。

## 学習内容4  
- **タグ**: sed, コマンド  
- **タイトル**: sedコマンドにおける正規表現  
- **内容**:
```
sed -i 's|placeholder_background\.png|background/kari-background.png|g' db/seeds.rb
```
の左辺は正規表現だが右辺はタダの文字列、そのためエスケープが不要となる。
