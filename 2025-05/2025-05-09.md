## 学習内容1
- **タグ**: CI,エラー対応
- **タイトル**: CIジョブ実行に関するエラー対応
- **内容**:
今回経験したエラー対応についてまとめる。
１．CIワークフローで依存関係をインストールしていなかった
各ジョブ（scan_ruby／scan_js／lint）の冒頭にbundle install相当のステップがなく、GemやJSパッケージが未インストールのままツール実行→exit code 127
２．GitHub Actionsにないdocker-composeコマンドを記述していた
古いdocker-composeコマンドを呼ぶとcommand not foundになるのでdocker composeに置き換える
３．テスト用コンテナとActionsのPostgresが別ネットワーク
services: postgresで立ち上がるDBと、docker compose run webのコンテナが通信できず接続失敗（exit code 127）した。
テストはホスト（runner）上で bundle exec rails db:create db:migrate rspec を実行する方式に切り替えることで対応した。
４．.envファイルをenv_file:で読み込ませていたが、CIには存在しない
Composeが.envを探してnot found（→exit code 1）に、env_file:を削除し、必要な値は environment:やCIのenv:で明示的に渡す
５．binstub（bin/rails／bin/importmap など）に実行ビットが立っていない
コンテナ内でpermission denied（exit code 126）、git update-index --chmod=+x bin/* で実行権限をGitインデックスに反映
６．RSpec 実行時の環境設定ミス
RAILS_ENV=test が適用されず production（または development）用 DB を操作しようとして保護エラーになった。
spec/rails_helper.rbで自動的に'test'をセット、CIでもRAILS_ENV=testを指定。
７．ActiveRecord のメタデータ不一致
テストDBのar_internal_metadataが'development'になっていてdb:test:load_schemaが弾かれた。
rails db:environment:set RAILS_ENV=testを実行し、メタデータを'test'に更新。

## 学習内容3
- **タグ**: Importmap
- **タイトル**: Importmapとは
- **内容**:
ブラウザが直接モジュール（JavaScriptの部品）を読み込む仕組み。
config/importmap.rbで「このJavaScriptの部品はあのCDNのURLから取ってきて」と指定。
HTMLの`<script type="importmap">`で読み込むことで使用可能に。
モジュールを自分のパソコンにダウンロードする必要がなく、ビルドツール（Webpackなど）も不要。

## 学習内容7
- **タグ**: Sass,CSS
- **タイトル**: Sass（CSS プリプロセッサ）
- **内容**:
CSSをより効率的・保守的に書くための拡張ツール。
人間が書きやすいSass記法で記述したファイルをコンパイルし通常のCSSファイルとして読み取る。
・変数：色やフォントサイズなどを変数にしておくことで一箇所を書き換えるだけで全体に反映可能
・ネスト：例として以下の通り、.navbarはクラスセレクタ、aは要素セレクタ、&:hoverはカーソルを乗せた要素を対象とする。
```
.navbar {
  background: #333;
  a {
    color: #fff;
    &:hover {
      color: #ccc;
    }
  }
}
```
・継承：あるスタイルを別のセレクタに受け継がせて重複を減らす。
・SCSS：Sassの記法の一つで、CSSとほぼ同じ構文で書ける形式（一般的）。Railsサーバー起動時にSassからCSSへ自動でコンパイル。

## 学習内容7
- **タグ**: アセットパイプライン
- **タイトル**: アセットパイプラインとは
- **内容**:
Webページで使用する静的ファイル（CSS、JavaScript、画像など）を効率よく管理・配信する仕組み
・ファイルの結合：複数の CSS・JSファイルをひとつにまとめることで、HTTPリクエスト数を減らし、ページの読み込みを速くする。
・圧縮：不要な空白やコメントを取り除き、ファイルサイズを小さくする。
・ハッシュ付与：application-4a1b2c3d.css のようにファイル名にハッシュを付けることで、ブラウザのキャッシュを正しく制御し、変更時のみ再取得させる仕組み。
・前処理（Preprocessing）：Sass（.scss）やCoffeeScript、画像の最適化など、必要なコンパイル・変換を自動で行うことが可能。

## 学習内容7
- **タグ**: アセットパイプライン,Sprockets
- **タイトル**: Sprocketsとは
- **内容**:
SprocketsはRails標準のアセットパイプライン。
マニフェストファイル（app/assets/config/manifest.js）を読み込み、その指示に従いどのディレクトリ・ファイルを含めるかを決定。
最終的に public/assets ディレクトリにまとめられたファイルが生成され、Web サーバから配信される。

## 学習内容8
- **タグ**: enum
- **タイトル**: enum メソッドのシグネチャ
- **内容**:
Rails 7以降ではenumメソッドのシグネチャが変わった。
Rails 6まで：`enum role: { general: 0, admin: 1 }`（キーワード引数で渡せた）  
Rails 7以降：`enum :role, { general: 0, admin: 1 }`（最初に属性名のシンボル、次にハッシュ（あるいは配列）を渡す）
