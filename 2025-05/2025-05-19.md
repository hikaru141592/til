- **タグ**: DB, スキーマ  
- **タイトル**: 本番環境でのSeedデータ利用(heroku) 
- **内容**:  
  - `heroku run rails db:seed --app アプリ名`で流し込む。
  - その際事前にマイグレーション（`heroku run rails db:migrate --app アプリ名`）し忘れがないよう注意。
  - 正しく流し込めたかはコンソール（`heroku run rails console --app アプリ名`）で確認可能。

## 学習内容2  
- **タグ**: アセット  
- **タイトル**: アセットの事前コンパイル
- **内容**: 
`rails assets:precompile`は、Railsアプリで使う静的アセット（JavaScriptやCSS、画像など）を本番用にまとめてビルドし、最適化しておくコマンド。  
処理後の成果物を public/assets（Rails7以降はPropshaftの設定次第でpublic/.assets）に出力。  
本番環境では毎リクエストごとにアセットの処理をするのは重く危険なので、事前にビルドして静的ファイルとして配信する。  
開発環境では、デフォルトでファイルをその場で読み込む「ライブリロード」機能があるため、通常はassets:precompileを手動で実行しなくても変更が反映されるが、
本番環境では事前に必ずこのタスクを実行しておく必要がある。

## 学習内容3  
- **タグ**: アセット  
- **タイトル**: 画像ファイルをAssetPipeline経由で読み込む
- **内容**: 
`app/assets/images`以下に画像を配置し使用する場合、`config/initializers/assets.rb`に
```
Rails.application.config.assets.paths << Rails.root.join("app/assets/images")
```
を追加する必要がある。その後アセットをビルド・反映するために、プレコンパイルをする必要がある。
```
docker compose run --rm web rails assets:precompile
docker compose restart web
```
