## 学習内容1  
- **タグ**: Rails, AssetPipeline, CSS
- **タイトル**: ハッシュ付きCSSの再ビルドが反映されない場合について
- **内容**:  
 1. Rails のアセットパイプラインはCSSファイル名の末尾に英数字のハッシュを付与し、キャッシュ制御を行う（例: `application-3f5a2b.css`）。  
    こうすることでブラウザが古いファイルを使い続けないようにし、新しいファイルを読み込ませる。ただしマニフェストの更新が追いつかずRailsが古いハッシュ名を参照し続けることがある。   
 2. SCSS/CSSを編集して `npm run watch:css`や`npm run build:css`等でビルドしても、既存の `public/assets` 内の古いハッシュ付きファイルが残っているとリンク先は更新されず、古いCSS が読み込まれる。  
 3. `bin/rails assets:clobber` を実行して `public/assets` 配下とマニフェストをまるごと削除し、古いハッシュを一掃する。  
 4. `npm run build:css` 等で新たにビルドし、新しいハッシュ付きCSSファイルを生成する。  
 5. `docker compose down && docker compose up` などでサーバーを再起動すると、`stylesheet_link_tag` が新しいハッシュ付きファイルを指すようになる。  
 6. ブラウザをハードリロード（Ctrl+F5）して、キャッシュを無視して新 CSS を読み込ませる。  
- **ポイント**:  
  - AssetPipeline のキャッシュクリアには clobber + サーバ再起動が必須。  
  - ブラウザ側もハードリロードして初めて新アセットが反映される。  
  ※Railsの開発環境では、Digest（ハッシュ）付きアセットを無効化して運用する場合も多く、その場合はビルドし直すだけで常に同じapplication.css が配信されassets:clobberが不要になることがある。

## 学習内容2  
- **タグ**: Rails, AssetPipeline, CSS, メモ
- **タイトル**: CSS編集時手順メモ
- **内容**:
1. ファイル構成と役割  
  - `app/assets/stylesheets/_variables.scss`  
    サイト全体で使う色・スペーシングの変数を定義  
  - `app/assets/stylesheets/_bootstrap-custom.scss`  
    Bootstrap のデフォルト変数を `_variables.scss` の値で上書き  
  - `app/assets/stylesheets/application.scss`  
    ①変数→②Bootstrap上書き→③Bootstrap本体→④カスタムスタイル の順に `@import`  
  - `app/assets/stylesheets/_custom.scss`  
    自作スタイル（背景色、コンテナ幅、フォーム、ボタン、メッセージボックス、フッターなど）をまとめて定義  
  - `app/assets/builds/application.css`  
    上記SCSSをコンパイル＋PostCSSで整形した最終的なCSS
2. CSS編集～ブラウザ反映の流れ  
  - SCSSを編集＆保存  
  - (開発中) `docker compose run --rm web bash -lc "npm run watch:css"` を動かしておくと、保存のたび自動ビルド  
  - 停止中なら手動で `npm run build:css`  
  - Railsアセットをリセット (古いハッシュ付きファイルを消す) するには、 `docker compose run --rm web bash -lc "bin/rails assets:clobber"`
  - コンテナ再起動&ブラウザでCtrl+F5
