## 学習内容1  
- **タグ**: Heroku  
- **タイトル**: Heroku CLIの基本コマンド  
- **内容**:  
```
heroku login            # Herokuにログイン（ブラウザ認証を起動）
heroku create           # 新規Herokuアプリを作成しgit remoteを追加
heroku apps             # 所有しているHerokuアプリの一覧を表示
heroku git:remote -a < app-name >     # 既存アプリをgitリモート「heroku」に追加
git push heroku main    # コードをHerokuにプッシュしビルド＆デプロイ
heroku open             # デプロイされたアプリをブラウザで開く
heroku ps               # 実行中のDyno状態を確認
heroku ps:scale web=1   # Web Dynoを1台にスケール
heroku ps:scale web=0   # Web Dynoを停止してDyno時間を節約
heroku logs --tail      # アプリのログを最新からリアルタイム表示
heroku config           # 環境変数(Config Vars)を一覧表示
heroku config:set KEY=VALUE          # 環境変数を設定
heroku addons            # アドオン一覧を表示
heroku addons:create heroku-postgresql:essential-0      # PostgreSQLをessential-0プランでプロビジョニング
heroku addons:upgrade heroku-postgresql:standard-0      # PostgreSQLをstandard-0プランにアップグレード
heroku addons:destroy heroku-postgresql --confirm < app-name > # PostgreSQLアドオンを削除（確認付き）
```

## 学習内容2  
- **タグ**: デプロイ  
- **タイトル**: デプロイする際のGem  
- **内容**:
Dockerfileに`FROM ruby:3.2.2`のような指定があってもそれははローカル用。
ローカル開発やDockerHub／ Container RegistryにイメージをプッシュするときにはDockerfileが使わるが、HerokuのBuildpack方式（git push heroku main）等でデプロイする場合、Dockerfile は参照されず、Gemfileの中のruby "バージョン" 宣言を見てRubyバージョンを決定する(Gemfileだがgemとして宣言するわけではない)。

## 学習内容3  
- **タグ**: デプロイ, Heroku 
- **タイトル**: Dynoを節約し無駄な課金を防ぐ
- **内容**:
HerokuではDynoをゼロにスケールして止めておくと無駄な課金を防げる。
```
heroku ps:scale web=0 --app mysterious-fjord-00343 # 停止（web Dyno を 0 にスケール）
heroku ps:scale web=1 --app mysterious-fjord-00343 # 再開するとき（web Dyno を 1 に戻す）
```

## 学習内容4
- **タグ**: Heroku, Buildpack, CSSBundling
- **タイトル**: Node.jsビルドパック未設定によるCSSプリコンパイルエラー対応
- **内容**:
  1. デプロイ時に `cssbundling-rails: No suitable tool found for installing JavaScript dependencies` エラー発生  
  2. 原因は Ruby ビルドパック単体では Node.js／npm が提供されないため  
  3. `heroku buildpacks:add --index 1 heroku/nodejs --app <app-name>` で Node.js ビルドパックを先頭に追加  
  4. `heroku buildpacks:add heroku/ruby --app <app-name>` で Ruby ビルドパックの順序を確保  
  5. package.json に `"engines": { "node": "18.x" }` を追記して Node バージョンを固定(推奨されるが今回はこれは省略)  
  6. 再デプロイ後に assets:precompile が成功

## 学習内容5
- **タグ**: Heroku, PostgreSQL, DATABASE_URL
- **タイトル**: ENV.fetch("DATABASE_URL") KeyError によるクラッシュ解消
- **内容**:
  1. production 環境で `url: <%= ENV.fetch("DATABASE_URL") %>` が原因で KeyError 発生し H10 クラッシュ  
  2. `heroku addons --app <app-name>` でアドオン未追加を確認  
  3. `heroku addons:create heroku-postgresql:essential-0 --app <app-name>` で Postgres アドオンをプロビジョニング  
  4. `heroku run rails db:migrate --app <app-name>` で本番マイグレーション実行  
  5. `heroku logs --tail --app <app-name>` で起動成功を確認
